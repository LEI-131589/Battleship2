## Guião 3 - Tarefa 2 (passo 4) — Data Class

### Nota sobre a Escolha do Code Smell
Inicialmente, a escolha recaiu sobre o *code smell* **Feature Envy**. No entanto, verificou-se que o Qodana Community (e as inspeções nativas do IntelliJ) não dispõe de uma regra de análise estática capaz de medir o acoplamento excessivo ou o acesso intensivo a dados externos (métrica `ATFD` — *Access To Foreign Data*). Impossibilitada a configuração de uma inspeção direta para *Feature Envy*, a demonstração foi reorientada para o *code smell* **Data Class**, utilizando a inspeção de encapsulamento `PublicField` alinhada com um limiar de tolerância no *Quality Gate*.

---

### Tabela de Caracterização da Inspeção

| Cheiro (Fowler) | Inspeção no IDE | ID da inspeção | Métrica / limiar | Limitações |
| :--- | :--- | :--- | :--- | :--- |
| **Data Class** | `'Public' field` | `PublicField` | `Public fields` / 18 | O Qodana Community não possui um detetor heurístico nativo dedicado que identifique automaticamente a ausência de comportamento ou a proporção entre *getters/setters* e métodos de negócio. A deteção baseia-se na inspeção de violação de encapsulamento (`PublicField`), exigindo a definição de um limiar absoluto no *quality gate* (`maxProblems: 18`) para ignorar avisos legados e sinalizar a introdução de novas classes de dados expostas. |

### Reflexão

- A ferramenta Qodana detetou corretamente a violação de encapsulamento associada ao *code smell* **"Data Class"** assim que o perfil personalizado foi configurado com a inspeção `PublicField` e o *quality gate* do workflow foi ajustado para o limiar do projeto (`maxProblems: 18` / `fail threshold: 18`).

- Durante a execução da *quality gate*, o *workflow* do GitHub Actions falhou como esperado ao introduzir a classe `ShipDataHolder` com atributos públicos (elevando o total de problemas para 23, ultrapassando o limite de 18). Após a remoção do ficheiro com o *code smell*, o número de violações regressou ao baseline de 18 legados, permitindo que a execução passasse a **Verde (Success)**.

- A principal limitação do Qodana no âmbito da deteção de **Data Class** prende-se com a dependência de análises sintáticas de visibilidade. Enquanto a literatura (*Martin Fowler / Object-Oriented Metrics in Practice*) define a Data Class através da falta de comportamento próprio combinada com o acesso externo intensivo (*Feature Envy* / `ATFD`), o Qodana apenas avalia a exposição pública de atributos de forma isolada, não medindo a transferência ou o acoplamento de lógica entre classes.
